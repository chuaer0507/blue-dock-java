# 任务

> 功能说明（从产品能力清单同步）。实现以 `docs/contract/api-contract.md` 与后端代码为准。

## 范围

### 概念

- **任务颜色（自定义色块）**
- **任务计划时间（start_at / end_at）**
- **任务描述（富文本）**
- **任务聊天室（dialog_id）**
- **任务工作流（自定义流程状态）**
- **任务提醒推送（即将超时 / 已超时）**
- **负责人与协作者**
- **任务优先级**
- **任务关联（消息提及 / 任务 ↔ 任务）**
- **子任务的限制（嵌套 / 数量 / 跨项目）**
- **子任务是什么**
- **任务标签（项目内独立）**
- **任务可见性（3 级）**

### 能力（怎么做）

- 归档任务 / 取消归档
- 任务附件上传与下载
- 标记任务完成 / 取消完成
- 复制任务（含子任务、附件、内容）
- 完整创建任务（详情页所有字段）
- 快速创建任务
- 在对话中用 @# 创建或关联任务
- 删除任务与回收站恢复
- 编辑任务基本信息（标题 / 描述 / 负责人）
- 拖拽任务换列 / 修改工作流状态
- 任务跨项目移动
- 重复 / 循环任务
- 任务列内排序
- 创建子任务
- 任务模板的创建与使用

## 核心概念

### 任务颜色（自定义色块）

## 定义
任务 `color` 字段允许用户给任务卡片打一个独立颜色，独立于优先级颜色、标签色块。常用于「重点跟进」「待回复」「等待审核」等用户自定义视觉标记。

## 数据形态
- 字段：`color`（16 进制色值字符串，如 `#FFAA00`，或空表示无）
- 与优先级色（落库 `priority_color` / wire `priorityColor`）同时存在时，**`color` 覆盖优先级色显示在卡片顶部色条**
- 与标签色块互不干扰，标签色显示在卡片底部

## 入口
- 桌面端：任务详情页 → 「颜色」选择器（圆形色板）
- 桌面端：看板视图任务卡右键 → 「设置颜色」
- 移动端：详情页字段区滑动到颜色 → 点选

## 取消颜色
- 在颜色选择器顶部选「无颜色」或「默认」
- 服务端写空字符串，看板卡顶恢复默认优先级色或灰色

## 与「优先级」「标签」的区别
- 优先级（`task.field.priority`）来自全局枚举，有语义
- 标签（`task.field.tag`）按项目分类，有语义
- 颜色无语义，只是视觉强调，按个人 / 团队约定使用

## 不支持
- 不能按颜色筛选
- 颜色不可批量改
- 子任务颜色不会自动继承父任务

### 任务计划时间（start_at / end_at）

## 定义
BlueDock 任务用两个字段描述时间：
- `start_at`：计划开始时间
- `end_at`：计划截止时间（俗称 deadline）

两者都可空。**填入 end_at 才能启用循环重复、到期提醒、日历展示。**

## 在哪里能看到
- 任务详情页 → 「计划时间」字段
- 任务卡片右下角倒计时 / 日期标签
- 日历视图：按 start_at→end_at 跨日条显示
- 甘特图视图：按 start_at→end_at 长度条显示

## 时间格式
- 桌面端可单选日期或日期+时分
- 默认是「日期」级别（无时分），含时分时存秒级精度
- 全天任务则 end_at 自动设为当天 23:59:59

## 与其他字段联动
- **重复循环**（`task.recurring`）依赖 end_at 计算下一次 loop_at
- **到期提醒**（ProjectTaskPushLog）按 end_at 触发推送（默认到期日推送、超期再推送）
- **日历视图** 只显示有 start_at 或 end_at 的任务
- **完成时间**（complete_at）与计划时间无关，是否超期由 complete_at vs end_at 比较

## 不支持
- 不能只设 start_at 不设 end_at 来启用循环
- 不能录工时（time_estimate / time_log 字段不存在）
- 修改 end_at 不会回填已生成的循环任务实例

### 任务描述（富文本）

## 定义
BlueDock 任务描述（`description` 字段 + `ProjectTaskContent` 表）支持富文本编辑，包括加粗、列表、链接、代码块、表格、图片、@ 提及成员等。短描述存 `description`（500 字符快照），完整富文本存 `ProjectTaskContent` 表，每次保存生成新版本记录。

## 在哪里能看到
- 任务详情页正中央富文本区
- 卡片视图鼠标悬停显示描述前 500 字符
- 搜索结果按 description 做文本匹配

## 编辑器能力
- 文本：粗体、斜体、下划线、删除线、代码、行内代码、引用
- 块级：标题、有序 / 无序 / 任务列表、代码块、引用、分割线
- 媒体：图片粘贴 / 拖入 → 自动上传 → 内嵌
- 互动：@ 成员（输入 @ 唤起选人面板，会同时通知）
- 链接：URL、内部任务链接（点击直接跳转）

## 自动保存
- 失焦自动保存
- 实时通过 WebSocket 同步（`task.created` / `task.updated` / `task.deleted` → 项目成员；见 [realtime.md](../../architecture/realtime.md)）
- 保存生成 ProjectTaskContent 版本，但目前没有 UI 让用户回滚

## 不支持
- 描述不能超过 50000 字符（HTML 含标签算），超长会被截断保存
- 不能直接挂附件，附件走独立的「任务附件」区
- 没有协同光标 / 实时同步光标位置（只是双方各自看到最新版本）

### 任务聊天室（dialog_id）

## 定义
BlueDock 每个**主任务**可以拥有一个独立聊天室（`dialog_id` 字段，对应 `WebSocketDialog` 表），用于负责人、协作者、可见用户在任务上下文中讨论。第一次打开任务对话区时按需创建，未启用前 dialog_id 为 0。

## 入口
- 桌面端：任务详情页 → 顶部「💬 任务对话」按钮 → 唤起侧边对话面板
- 桌面端：左侧 `messenger.group.howto.create` 创建的群外，任务对话作为独立类型显示在「最近消息」列表
- 移动端：任务详情页底部「💬」入口

## 谁能参与
- 默认：负责人、协作者、可见用户均可读写
- 不在 `task.field.visibility` 命中的用户看不到聊天室
- 项目管理员若不在任务可见范围内，也看不到对话
- 落地：`GET /api/project/task/dialog` 经 `TaskDialogMembership` 按 visibility 同步群成员；`dialog/message/*` / `dialog/lists` 经 `TaskDialogAccessBridge` 二次校验；可见性或任务人员变更时重同步；系统机器人成员不同步踢出

## 与「关联」的关系
- 在任务聊天室里输入 `@#` 关联其他任务，会产生 `task.related` 记录
- 在群聊里 `@#` 关联到这个任务，产生反向关联（任务详情页能看到「相关消息」）

## 删除联动
- 任务被 `task.delete-restore` 删除后，dialog_id 保留不清理
- 恢复任务时，聊天室可继续使用，历史消息完整保留

## 不支持
- 子任务（parent_id > 0）不能开独立聊天室
- 任务对话不能与外部用户共享（必须是任务可见用户）
- 任务对话不能匿名 / 不能开私聊模式（始终多人）

### 任务工作流（自定义流程状态）

## 定义
BlueDock 工作流由 `ProjectFlow`（一个项目可有多套）+ `ProjectFlowItem`（每个流程节点）实现。常见用法是把任务从「待办 → 设计 → 开发 → 测试 → 上线」自定义为多个流转节点，比"完成 / 未完成"二值粒度更细。

## 关键字段（ProjectFlowItem）
- `name`：节点名（如「待开发」）
- `status`：节点类型，`start` 起点 / `end` 终点 / 其他普通节点
- `turns`：可流转到的节点 id 列表（流转规则）
- `userIds`（落库 `user_ids`）：节点负责人（限制只有这些人可以操作进入此节点）
- `usertype`（落库 `user_type`）：流转模式（如限制只能由当前负责人流转）
- `color`：节点色块（看板视图色条）
- `columnid`：可绑定到具体项目列，拖列时联动改 flow_item_id

## 任务上的字段
任务存 `flow_item_id` + `flow_item_name`，前端用此显示当前所处节点。

## 与「列」（column_id）的关系
- 列只是看板的物理分栏，与状态不一定一一对应
- 启用工作流后，看板视图按 `column_id` 分组，工作流视图按 `flow_item_id` 分组
- 节点配 `columnId` 时，拖列与改状态**双向**联动：`task/flow`·`update?flowItemId` 改状态会写绑定列；`project/sort` / `task/update?columnId` / `task/move` 换列会写绑定节点
- 不配则列与状态独立

## status=end 的特殊行为
- 拖任务到 status=end 的节点 → `complete_at` 自动写入 → 任务被标记完成
- 拖回非 end 节点 → complete_at 不会自动清空（除非显式取消完成）

## 不支持
- 单流程不能超过 10 个节点（最多 10 节点）
- 不能跨项目共享工作流
- 工作流配置改名 / 改色不会回填历史任务的 flow_item_name 快照

### 任务提醒推送（即将超时 / 已超时）

## 定义
任务到期提醒由「任务提醒」机器人（task-alert）通过私聊发送模板消息。推送记录在 `ProjectTaskPushLog` 表，按 `type` 区分：

- `0` — 新任务（被分配时）
- `1` — 任务**即将超时**（截止时间 end_at 前约 1 小时）
- `2` — 任务**已超时**（end_at 过后约 1 小时，且任务未完成）
- `3` — 任务时间被修改

即将超时 / 已超时两类按用户 + 任务去重，避免重复推送。

## 触发条件
- 任务必须设置截止时间 `end_at`
- 管理员需在管理员应用「APP 推送」中开启推送（未开启则定时提醒不运行）
- 后端定时任务扫描命中后，向任务负责人 + 协助人发送，文案如「您负责的任务即将超时」「您协助的任务已经超时」

## 推送渠道
- **站内消息**：「消息」列表中 task-alert「任务提醒」机器人的私聊会话
- **桌面端**：经 Electron 系统通知弹出
- **移动端**：离线 / 后台用户经 APP 推送触达，见 `mobile-client.notify`

## 不支持
- 不能为单条任务自定义提醒时间偏移（如「提前 2 小时」），固定为到期前约 1 小时、超期后约 1 小时各提醒一次
- 不能给非负责人 / 非协助人推送
- 已完成或已归档的任务不再推送

## 不支持 / 边界

- "`#` 任务面板只能关联已有任务，没有「新建任务」入口，也没有负责人 / 截止时间字段"
- BlueDock 任务没有 time_estimate / time_log 字段，不能记录工时
- 一个任务必须至少有一个负责人，不能"无主"
- 一个任务最多 50 个子任务
- 不支持只设开始时间不设结束时间（end_at 是计算到期与循环周期的依赖）
- 不能为单条任务自定义提醒提前量，统一为到期前约 1 小时
- 任务删除不会自动删除聊天室
- 任务名为空无法保存
- 任务名称必填且最长 255 字符
- 任务复制不会带走附件
- 任务标签按项目隔离，不能跨项目共享
- 任务模板不能跨项目共享，除非站点设置 task_template_share 开启
- 任务没有「整项目置顶」字段，只能调列内顺序
- 任务颜色不影响优先级、状态、可见性
- 优先级与排序无关，不会自动让高优先级冒泡到列首
- 优先级数据是全局共享的，不能按项目独立配置（除非用 `task.field.color` 单独覆盖）
- 修改循环周期不会回填已生成的实例
- 公开访问链接、订阅记录不复制
- 关联不带过去字段数据（不是软链接，只是关系记录）
- 关联建立后不会自动同步任务字段到消息
- 关联是平级的，不会形成父子层级（要拆层级用 `task.subtask`）
- 创建后任务默认进入所在列底部（列头「+」则加到列顶）
- 删除任意一方任务不会自动删除关联记录
- 删除后默认仅在回收站近期记录中保留，超过保留窗口会被定时清理
- 删除消息不会删除已建任务
- 协作者不能完成任务，只有负责人能（或有 TASK_UPDATE 权限的项目角色）
- 单个任务最大标签数 10 个
- 单个父任务最多 50 个子任务
- 单文件大小受站点设置限制
- 可见性只控制「能不能看到这个任务」，不控制评论、附件的二级权限
- 复制不会保留归档状态、删除时间
- 复制不会带走 dialog_id（任务聊天室）和完成时间，目标任务是全新一份
- 复制任务会重置 dialog_id，新任务有自己的全新聊天室
- 多人同时拖动时，最后一次写入覆盖前面（无冲突合并）
- 子任务不能再嵌套子任务（一级深）
- 子任务不能单独设置可见性，强制继承父任务
- 子任务不能独立开聊天室，强制使用父任务的 dialog_id
- 子任务不能跨项目（强制与父任务同 project_id）
- 子任务不能跨项目（必须与父任务在同一个项目）
- 子任务仅支持 1 层（不能在子任务下再建子任务）
- 子任务必须与父任务在同一项目，不能跨项目
- 子任务最多 1 层（不能在子任务下再建子任务）
- 子任务模板不支持嵌套子任务
- 子任务的颜色不会继承父任务，需要单独设
- 子任务跟随父任务一起移动，不能单独移动子任务
- 子任务（parent_id > 0）不能独立上传附件
- 完成不等于归档，归档要走 `task.archive`
- 工作流最多 10 个状态 / 流程
- 工作流状态绑定 `columnId` 时，拖列联动改 `flowItemId`；不绑定时各自独立
- 工作流的 status=end 节点会自动标记 complete_at，无法关闭这一联动
- 已删除任务不能编辑、不能完成、不能加子任务，必须先恢复
- 归档不等于删除，归档任务保留全部字段、关联、附件
- 归档不等于完成，归档任务可以是未完成状态
- 归档任务不会出现在默认列表，但仍能搜索到
- 快速创建不支持设置截止时间、负责人、协作者等高级字段（可选优先级），如需用完整创建
- 所属项目已删除或已归档的任务不能恢复，只能删除
- 所属项目已被删除或已归档时，不再自动生成新的周期任务
- 拖动只改 column_id（所属列），不直接改 complete_at（完成时间）
- 排序变更不会进项目动态日志
- 描述不能直接附文件，需要单独走任务附件区
- 描述富文本上限 50000 字符（含 HTML 标签）
- 描述富文本最长 50000 字符
- 描述无版本回滚 UI，仅服务端保留历史（ProjectTaskContent 表）
- 改字段会即时写入并广播到所有项目成员，不需要点保存
- 改完成时间(complete_at) 和归档时间(archived_at) 不能直接编辑，必须用 `task.complete` / `task.archive`
- 普通用户无法新增 / 修改优先级枚举，仅可选择
- 标签名最长 20 字符
- 模板不保存附件，只保存标题、内容、字段
- 没有 end_at（截止时间）的任务不会推送即将超时 / 已超时提醒
- 消息菜单「新任务」仅对文本消息可用，图片 / 文件 / 语音消息没有该选项
- 父任务删除会级联软删所有子任务
- 父任务完成不会自动完成所有子任务，需要单独操作
- 父任务完成不会自动完成所有子任务，需要手动或 `task.subtask.howto.create` 后逐个处理
- 移动端不支持拖动，需进详情改字段
- 管理员未开启「APP 推送」设置时，到期 / 超期定时提醒整体不发送
- 负责人 / 协作者不会自动获得评论权限以外的项目权限
- 跨时区显示按用户所在时区，但服务端统一存 UTC
- 跨项目拖动不支持，跨项目要用 `task.move.howto.cross-project`
- 跨项目移动不会迁移任务聊天室（dialog_id 保留但不再属于目标项目对话列表）
- 跨项目移动会清空项目级标签（`task.field.tag`），按目标项目重新打
- 重复任务不能在子任务上独立设置（subtask 不支持 loop）
- 重复任务在完成的瞬间生成下一份，详见 `task.recurring`
- 重复任务的下一份在「上一份被标记完成时」生成，不是按日历预生成
- 项目管理员不会自动看到 visibility=2/3 的任务，除非被加入任务人员
- 颜色不参与筛选 / 排序，仅做视觉强调
