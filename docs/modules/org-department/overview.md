# 部门

> 功能说明（从产品能力清单同步）。实现以 `docs/contract/api-contract.md` 与后端代码为准。

## 范围

### 概念

- **部门负责人与部门管理员**
- **部门是什么**

### 能力（怎么做）

- 任命部门管理员
- 新建或修改部门
- 罢免部门管理员
- 删除部门
- 设置项目负责人视角和共用部门范围
- 查看与管理部门列表
- 同步部门成员

## 核心概念

### 部门负责人与部门管理员

## 定义
部门里有两种"领导"角色，权限近似但有差别：

- **部门负责人（owner）**：每个部门唯一，存在部门表的 `owner_userId` 字段；自动成为部门群群主（role=1）
- **部门管理员（deputy）**：每个部门可多人，存在 `user_department_owners` 表；在部门群里 role=2

两者在前端常合称"部门负责人"，在 RAG 检索中"deputy = 部门管理员"。

## 关键属性
- 任命/罢免接口分别为 `department__addDeputy` / `department__deleteDeputy`，仅系统管理员可调用
- 任命部门管理员会自动把该用户加入部门（写入 `users.department`）并加入部门群（important=true 不可被普通群操作打散）
- 部门负责人是 owner_userId 字段的唯一持有人；变更走 `department__add`（传 id + 新 owner_userId 即编辑）

## 能做什么
开启系统设置「部门负责人视角」后：
- 只读查看本部门及所有下级部门成员参与的**项目**与**任务**
- 不能修改项目设置、任务、成员
- 可在仪表盘查看团队任务总览，见 `dashboard.team`
- 可通过右上角头像菜单或项目列表打开项目负责人视角，见 `org-department.deputy-view`
- 仪表盘与项目负责人视角共用部门范围，但项目列表是否启用只读视角由独立开关控制
- 「项目级开关」：每个项目可单独关闭"部门负责人视角可见"（`projects.department_owner_view`）

## 与其他概念的关系
- 与系统管理员：互不重叠；系统管理员有进入团队管理的权限，部门负责人仅有查看下属数据的只读视角
- 与项目负责人：不冲突；同一用户可在 A 部门做负责人 + 在 B 项目做负责人

### 部门是什么

## 定义
部门（department）是 BlueDock 用于描述公司组织结构的树形单位。每个部门有名称、上级部门（parent_id）、唯一的部门负责人（owner_userId）和可选的部门管理员（deputy）。部门之间通过 parent_id 形成树形结构，最多 3 级。

## 关键属性
- **name**：部门名称，2-20 字，不能含特殊符号或字符串 `(M)`
- **parent_id**：上级部门 ID；为 0 表示顶级部门
- **owner_userId**：部门负责人 userId，必填且唯一
- **deputy_userIds**：部门管理员列表，存于 `user_department_owners` 表，可多人
- **dialog_id**：每个部门自动绑定一个部门群（group_type=`department`），成员关系与部门成员对齐

## 与其他概念的关系
- **用户与部门**：用户的 `department` 字段保存其所在部门 ID 列表，用逗号包围（如 `,1,3,`）；同一用户可属于多个部门
- **部门与群聊**：每个部门有一个部门群，部门负责人是群主、部门管理员在群里 role=2
- **负责人视角**：开启系统设置「部门负责人视角」后，负责人/管理员可只读查看本部门及所有下级部门成员参与的项目和任务，见 `org-department.deputy`

## 入口
管理入口仅限系统管理员：`org-department.entry`

## 不支持 / 边界

- owner_userId 必填且必须是有效用户；一个用户最多负责 10 个部门
- 一个部门只能有 1 个部门负责人（owner_userId），不能空
- 不能把部门负责人（owner_userId）任命为部门管理员，会报「不能将部门负责人任命为部门管理员」
- 不能罢免部门负责人（owner_userId）；接口对 owner_userId 调用时仅做悬挂记录清理，不会把负责人踢出部门或群
- 不能选自己的子部门作为上级（防成环）
- 仅系统管理员可调用
- 仅系统管理员可调用，部门负责人本人无权任命
- 任命部门管理员**会自动**把用户加入该部门（写入 `users.department`），并加入部门群（role=2、important=true）
- 全系统最多 200 个部门
- 列表不分页，全量返回（受全系统 200 个上限保护）
- 列表按 id 升序，不支持自定义排序
- 删除会**自动**把所有成员从该部门移出（`users.department` 字段中移除该部门 ID）
- 删除会**自动解散**该部门绑定的部门群（dialog_id 对应群）
- 删除后无法恢复
- 同一用户最多负责（owner_userId）10 个部门
- 同步与 LDAP 拉取无关：BlueDock 内部不直接通过此接口对接 LDAP
- 同步是"子部门成员合并到当前部门"，**不是**反向（不会把当前部门成员推到子部门）
- 同步是单向、追加：只新增 `users.department` 里没有该部门 ID 的用户，已在的不重复加
- 含子部门的部门**不能直接删**，会报「含有子部门无法删除」，必须先删所有子部门
- 已 disable_at 的用户被跳过，不会同步进部门或部门群
- 操作幂等：重复任命已是 deputy 的用户不会报错
- 操作幂等：重复罢免非 deputy 用户不报错也不做任何事
- 普通成员看不到全量部门列表，只能看自己所在部门（info__departments，最多 10 条）
- 每个父部门最多 20 个直属子部门
- 每个部门最多 20 个直属子部门
- 没有子部门时返回成功但不做事，提示「同步完成，子部门中没有成员需要同步」
- 没有选择任何部门时不能保存范围
- 罢免操作**会同时**：① 删除 `user_department_owners` 记录；② 从 `users.department` 移除该部门 ID；③ 让用户退出部门群
- 罢免部门管理员会同步把他从该部门移除并退出部门群
- 负责人视角只增加只读范围，不改变本人原有项目权限
- 部门不能跨实例迁移
- 部门名称必须 2-20 字，不能含特殊符号（`~!@#$%^&*()+-_=.:?<>,`）或字符串 `(M)`
- 部门层级最多 3 级（顶级 + 2 层子部门）
- 部门层级最多 3 级，第 4 级会被接口拒绝
- 部门管理员不能罢免自己（只有系统管理员能罢免）
- 部门范围和项目列表开关保存在当前浏览器，不跨设备同步
- 部门负责人/管理员不等于系统管理员（userIsAdmin），不能进系统设置
- 部门负责人不能同时是自己部门的部门管理员（接口会拦截）
- 项目可单独关闭负责人视角可见性，关闭后不会被纳入
- 项目负责人视角只能只读查看额外项目，不授予修改权限
